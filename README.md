# Skreenshare проектор

Показывает экран и звук Windows-компьютера на Android-проекторе (например TouYinGer H6) по домашнему Wi-Fi.
Без кодов, без интернета, без аккаунтов. Видео кодирует видеокарта NVIDIA (NVENC, H.264), задержка обычно 100–200 мс. Звук и картинка синхронизированы по меткам времени (lip-sync).

Состоит из двух программ:

| Файл | Куда ставить |
|---|---|
| `skreenshare-proektor.exe` | на компьютер с Windows 10/11 и видеокартой NVIDIA (GTX 900-й серии и новее) |
| `skreenshare-proektor.apk` | на проектор (Android 5.0+) |
| `skreenshare-proektor-compat.apk` | запасной вариант для проектора: Android 4.4+, максимально «старый» формат (см. ниже) |

Проект сделан на основе приватного репозитория `technosamura1/screenshare` (Rust, захват экрана DXGI, WASAPI loopback, NVENC);
ручные коды и обход NAT убраны, вместо них — автопоиск в локальной сети и свой UDP-протокол.

## Установка на проектор
1. Скачайте `skreenshare-proektor.apk` (GitHub → Releases) на компьютер.
2. Любой из способов:
   - **Флешка**: скопируйте apk на флешку, вставьте в проектор, откройте файловый менеджер проектора и запустите файл;
   - **Ссылка**: загрузите apk в облако (Google Диск / Яндекс Диск), откройте ссылку в браузере проектора и скачайте файл;
   - **По USB-отладке (adb)**: `adb connect IP_проектора` → `adb install skreenshare-proektor.apk`.
3. Если проектор ругается на «неизвестные источники» — разрешите установку из этого источника (Настройки → Безопасность).
   **Если проектор пишет «файл не поддерживается» / «не удалось установить»:**
   - убедитесь, что файл скопирован целиком (размер около 650 КБ) и имя заканчивается на `.apk`; не открывайте его из «предпросмотра» файлового менеджера — сначала скопируйте во внутреннюю память (Download);
   - разрешите «неизвестные источники» для того приложения, из которого открываете файл (файловый менеджер/браузер);
   - попробуйте `skreenshare-proektor-compat.apk` (тот же ключ и то же имя пакета: ставится поверх, настройки не нужны);
   - надёжнее всего — по adb, он обходит встроенный установщик проектора. Самый простой способ — `install-on-projector.zip` из релиза: распакуйте, дважды щёлкните `install-on-projector.bat`, введите IP проектора (на проекторе заранее включите «Отладку» — 7 раз нажать «Номер сборки», см. README.txt в архиве). Скрипт сам скачает platform-tools от Google, поставит APK по Wi-Fi и запустит приложение (`tools/install-on-projector.bat` и `.ps1` в репозитории).
4. Запустите «Skreenshare проектор». Приложение само сразу начинает ждать компьютер (ничего нажимать не нужно), показывает своё имя и IP. Экран проектора не будет гаснуть.
   Выход — кнопка «Назад» на пульте.

## Использование
1. Проектор и компьютер должны быть в **одной сети Wi-Fi** (или компьютер по кабелю в тот же роутер).
2. На проекторе откройте приложение.
3. На компьютере запустите `skreenshare-proektor.exe` (установка не нужна). При первом запуске Windows спросит про доступ к сети — **нажмите «Разрешить»**
   (иначе проектор не найдётся). Первый запуск занимает пару секунд — программа распаковывает свои компоненты в `%LOCALAPPDATA%\skreenshare-proektor`.
4. Окно программы — это по сути одна большая кнопка **«Транслировать»**. Над ней — список **«Что показывать»**: по умолчанию «Весь экран», можно выбрать отдельный монитор или одно окно (см. ниже). Найденный проектор выбирается сам (если их несколько — выберите нужный в списке). Остановить — та же кнопка.
5. Ничего настраивать не нужно: по умолчанию Full HD, 60 к/с, **30 Мбит/с** (H.264, NVENC low-latency), звук включён. Битрейт подстраивается под Wi-Fi автоматически (см. ниже).
6. Если что-то не так — раздел **«Дополнительно»** (свёрнут): запасное качество Full HD 30 к/с или 720p, битрейт (можно до **80 Мбит/с**), авто-подстройка вкл/выкл, звук вкл/выкл и **сдвиг звука**.

### Показать только одно окно
В списке **«Что показывать»** (над кнопкой «Транслировать») кроме «Весь экран» есть:
- каждый монитор (если их несколько): «Экран 2 · 1920×1080»;
- каждое открытое окно по заголовку: «Окно: …». Список окон обновляется каждый раз, когда вы открываете меню (и раз в секунду, пока оно открыто).

Выберите окно и нажмите «Транслировать» — на проектор пойдёт только это окно (захват через Windows Graphics Capture, Windows 10 версии 1903 и новее; другие окна поверх него в кадр не попадают, курсор мыши виден).
Окно всегда показывается на «холсте» размера трансляции (обычно 1920×1080): оно масштабируется по размеру проектора с сохранением пропорций, лишнее место — чёрные полосы.
Если вы меняете размер окна во время трансляции, картинка сама подстраивается (проектор при этом не переподключается).
Если окно закрыли (или его не удалось захватить), трансляция **не останавливается**: программа переключается на весь экран и пишет об этом оранжевой строкой под кнопкой.
Особенности: свёрнутое окно программа при старте разворачивает (свёрнутое окно Windows не рисует); у окон некоторых защищённых программ (DRM) картинка может быть чёрной;
на Windows 10/11 Windows может рисовать жёлтую рамку вокруг захватываемого окна — это системная подсказка, убрать её нельзя.

### Автоподстройка битрейта
Проекторы на 2,4 ГГц Wi-Fi реально тянут 15–30 Мбит/с. Поэтому программа стартует с выбранного битрейта (30 Мбит/с) и каждую секунду смотрит отчёт проектора:
при потерянных кадрах или росте пинга она быстро снижает битрейт (до ~6 Мбит/с для Full HD) и потом медленно, ступеньками, возвращает его обратно — но не выше выбранного значения
(в «Дополнительно» его можно поднять до 80 Мбит/с; если авто-подстройку выключить — битрейт будет постоянным). Текущий битрейт и к/с видны в строке состояния под кнопкой.
Битрейт снижается по «остаточным» потерям — тем, что не удалось исправить дозапросом (см. «Потери пакетов»); одиночный всплеск потерь на него не влияет.
Скорость интернета тут ни при чём — важна только скорость Wi-Fi между ПК и проектором.

### Синхронизация звука и картинки
Компьютер ставит на видеокадры и на звук метки времени с одних и тех же часов в момент захвата (звук — с точностью до сэмпла).
Проектор берёт за главные часы позицию воспроизведения звука (`AudioTrack`) и показывает каждый кадр через `MediaCodec` ровно тогда, когда звучит звук с такой же меткой;
опоздавшие более чем на ~100 мс кадры пропускаются, дырки от потерянных пакетов заполняются тишиной, чтобы время не «уезжало». Буфер небольшой (~40–150 мс), общая задержка около 100–200 мс.
Если картинка стабильно опаздывает (слабый декодер), проектор чуть задерживает звук (до 150 мс), чтобы губы всё равно совпадали.
Новая настройка на ПК: **«Дополнительно → сдвиг звука»** (−300…+300 мс, «+» — звук позже) — для подгонки под конкретный проектор/Bluetooth-колонку.
Приложение на проекторе v0.2+ работает и со старым exe (без синхронизации), а новый exe со старым приложением тоже работает (картинка просто показывается сразу).

### Проверка с телефона (без проектора)
Приложение `skreenshare-proektor.apk` можно поставить на обычный Android-телефон в той же сети Wi-Fi, что и компьютер: оно так же само начинает слушать,
телефон появится в программе на ПК как «проектор». Картинка вписывается с чёрными полосами, поворот экрана (книжный/альбомный) поддерживается.

### Если проектор не находится
- Откройте на проекторе приложение и убедитесь, что в нём написан IP-адрес (вида 192.168.x.x).
- Нажмите в программе на ПК «Не находит проектор? Ввести IP вручную» и введите этот IP.
- В роутере выключите «изоляцию клиентов» / «AP isolation» (из-за неё устройства в Wi-Fi не видят друг друга). Гостевая сеть часто так и работает.
- Проверьте брандмауэр Windows: Параметры → Брандмауэр → «Разрешить работу с приложением» → отметьте `skreenshare-proektor.exe` для частных и общедоступных сетей.
- Порты: UDP 47800 (проектор) и 47801 (компьютер).

### Если лагает или звук хрипит
- **Подключите ПК к роутеру кабелем (Ethernet)** — это сильно помогает: Wi-Fi тогда нужен только на участке роутер → проектор.
- **Поставьте проектор поближе к роутеру** (лучше в прямой видимости). Если проектор умеет только 2,4 ГГц, он будет упираться в 15–30 Мбит/с, и битрейт сам снизится.
- Всё равно лагает — «Дополнительно» → «Full HD 30 к/с» или «HD 720p».
- Звук не совпадает с картинкой на глаз — подвиньте «сдвиг звука».

### Что нового в v0.5
- **Звук Opus** (если проектор умеет его декодировать; проверяется самотестом на устройстве), иначе прежний несжатый звук с копиями; буфер звука 80–120 мс, звук — главные часы.
- **Пейсер** отправки: всплеск до 12 пакетов, скорость 1,6× от битрейта; сокет проектора 8 МБ, повышенные приоритеты потоков.
- **Счётчики к/с**: отправлено → принято → показано (на ПК в строке состояния; на проекторе — по кнопке «ОК»/«Меню» на пульте или касанию).
- **Захват окна без жёлтой рамки** там, где Windows это разрешает (Windows 11); на остальных рамка остаётся, об этом показывается пояснение.
- Исправление совместимости APK для старых проекторов (два варианта, подпись v1+v2+v3).

### Потери пакетов (v0.4)
На 2,4 ГГц Wi-Fi теряется несколько процентов пакетов — это нормально, и программа к этому готова:
- **Дозапрос только потерянного.** Проектор через ~8 мс после появления «дырки» отправляет ПК список недостающих пакетов (NACK), ПК держит последние ~300 мс отправленных пакетов и досылает именно их (с ограничением скорости, чтобы дозапросы не забили канал).
  Целый ключевой кадр запрашивается, только если кадр не удалось дособрать за ~200 мс; запросы идут не чаще раза в 0,5 с, а если ответа нет — всё реже (до 4 с). «Петли ключевых кадров» нет.
- **Звук с запасом.** Каждый звуковой пакет (3 мс) несёт копию предыдущего: одиночная потеря незаметна. Оставшиеся дырки заполняются не жёсткой тишиной, а плавно затухающим повтором последних миллисекунд, ровно по длине дырки — синхронизация не сбивается.
- **Статистика** в строке состояния на ПК: «потери пакетов 3.1% (повторно отправлено 40/с, восстановлено 38)».
- **Проверка потерь без плохой сети:** запустите ПК-программу с переменной окружения `SS_SIM_LOSS` — доля исходящих пакетов, которую отправитель выбросит (видео, звук и дозапросы). Например, в PowerShell:
  `$env:SS_SIM_LOSS="0.05"; .\skreenshare-proektor.exe` (5%). Допустимы `0.05`, `5%`, `0,03`; по умолчанию выключено, в строке состояния появляется пометка «ТЕСТ».
- Автотест (без устройств): `cd proto && cargo test --release sim -- --nocapture` гоняет через эмулятор сети старую логику v0.3 и новую при 3–5% потерь (случайных и пачками). Результат (30 с, 30 к/с, ~16,6 Мбит/с):

  | потери | старая логика | новая логика |
  |---|---|---|
  | 3% случайные | 0,0 к/с, пауза до 29 с, 198 запросов ключевого кадра, звук: 3,0% дырок | 30,0 к/с, макс. пауза 150 мс, 1 запрос, звук: 0,14% дырок |
  | 5% случайные | 0,0 к/с, пауза 30 с, 198 запросов, звук: 5,2% | 30,0 к/с, пауза 161 мс, 1 запрос, звук: 0,35% |
  | 3% пачками | 0,6 к/с, пауза 7 с, 198 запросов, звук: 3,0% | 30,0 к/с, пауза 132 мс, 1 запрос, звук: 0,70% |
  | 5% пачками | 0,2 к/с, пауза 13 с, 198 запросов, звук: 4,8% | 30,0 к/с, пауза 166 мс, 1 запрос, звук: 1,69% |

  Накладные расходы дозапросов — около 2–4% битрейта. Это модель (не реальный Wi-Fi): она показывает, что логика не зацикливается, но не заменяет проверку на вашем проекторе.
- **FEC (избыточные пакеты) не делали:** дозапрос укладывается в бюджет задержки и для ключевых кадров, а FEC добавляет сложность и постоянный расход канала, который нельзя честно проверить без реального Wi-Fi.
- Известные пределы: интервалы дозапроса фиксированные (повтор через 40 мс) — при очень большом пинге (> 50–60 мс) часть дозапросов будет лишней; звуковая копия закрывает одиночную потерю, пачка из 3+ звуковых пакетов подряд заполняется затухающим повтором/тишиной.

## Ограничения (v0.5)
- Только Windows + NVIDIA. Нужен свежий драйвер (для NVENC).
- Трафик в сети не шифруется и не защищён PIN: любой в вашей сети может попробовать подключиться к проектору. Для домашней сети нормально.
- Один компьютер за раз; новый запуск перехватывает проектор.
- Звук: это звук, который играет на колонках ПК (WASAPI loopback), он продолжает звучать и на ПК — убавьте/выключите колонки ПК. Если на ПК ничего не играет, звук тишиной не идёт.
- Синхронизация звука зависит от того, насколько точно Android сообщает позицию воспроизведения (на дешёвых проекторах бывает погрешность — для этого и есть «сдвиг звука»).
- Курсор мыши рисуется программно; защищённое DRM-видео (Netflix в браузере) может быть чёрным.
- Приложение подписано одним общим ключом из репозитория (`android/release.keystore`) — это не секрет, обновления ставятся поверх.
- Реально проверялись: сборка, протокол (тесты на Rust и Kotlin с одинаковыми эталонными байтами), разбор/патч H.264, логика потерь (эмуляция сети на Rust; в Kotlin — юнит-тесты перенесённых классов, общей эмуляции для Kotlin нет). Захват окна (WGC) собран и проверен только на уровне компиляции и тестов геометрии (рамка «влезть с полосами»). Работа на живом железе (NVENC, захват окна, Wi-Fi 2,4 ГГц, реальная синхронизация на вашем проекторе, подстройка битрейта) не тестировалась — присылайте, что увидите.

## Сборка
- **Android**: `cd android && ./gradlew assembleRelease` (JDK 17+, Android SDK 34) → `android/app/build/outputs/apk/{standard,compat}/release/`. Задачи: `assembleStandardRelease` (Android 5.0+) и `assembleCompatRelease` (Android 4.4+, targetSdk 28).
- **Windows exe на Linux**: `tools/build-windows-on-linux.sh` (cargo-xwin, clang/lld; нужен свой облегчённый FFmpeg в `third_party/ffmpeg` — `tools/build-ffmpeg.sh`; затем `tools/make-import-libs.sh`; `tools/check-dlls.sh` проверяет exe).
- **Windows exe на Windows**: Rust + Visual Studio Build Tools + LLVM; распакуйте FFmpeg (`ffmpeg-n9.0-latest-win64-lgpl-shared-9.0.zip`) в `third_party/ffmpeg`,
  выполните `tools/make-import-libs.ps1`, затем `cargo build --release`. FFmpeg DLL упаковываются внутрь exe, поэтому exe один файл (~45 МБ).
- **CI**: заготовка `ci/build.yml` (не проверена). Чтобы включить GitHub Actions, скопируйте её в `.github/workflows/` — для пуша в эту папку токену нужен scope `workflow` (`gh auth refresh -s workflow`).
- Тесты: `cargo test -p proto` и `cd android && ./gradlew testDebugUnitTest`.
